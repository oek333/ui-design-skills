# Provenance: coherent-ui

**Claude Opus 5.5:** “This skill was written by Claude (model not recorded) operating in the claude.ai web app to distill a design conversation we had on 30 May 2026 about a tool I am building for working with collated manuscript witnesses. I had been designing a character-annotation layer over the collation and, in parallel, going back and forth with Codex, the agent building the tool’s interface. Codex kept bolting new controls onto the UI rather than re-deriving the whole screen each time it added a feature.

“The principles come from the message in which I asked for the skill and named the habit I wanted it to correct. I told Claude the agent ‘has this tendency to patch the UI instead of adding features in a stateful manner,’ and then defined the term: ‘By stateful I mean the property of a UI where it represents a unified visual state instead of a patched one. Do not interpret stateful as a technical term. It’s close to coherent, where the sum of all elements produces a coherent visual whole.’

“The restraint the skill insists on, that a feature should reuse or reduce surface rather than multiply it, comes from my brief at the start of the same conversation: ‘I want elegant and simple solutions not over-engineered solutions. Do not manufacture complexity,’ because the more complex the result, ‘the more likely I will have to deal with cognitive load to review it, the farther I will deviate from my vision.’

“The skill began with one instruction: ‘now give me the skill file for frontend design to share with the agent.’ That afternoon I pasted it into Codex with the words ‘Once I review the work and it is visually stateful as the skill explains, we will save it for future use,’ and then had it saved verbatim. It later shaped two Claude Code skills, friction-audit (5 June) and ux-prototype-handoff (17 June).”
